# DayDeck 설계 문서 (v0.1)

> Windows 11용 개인 일정 관리 도구: 할 일(Todo), 달력 일정, 메모, 알림
> 핵심 목표는 **해야 할 일을 잊지 않게 하는 것**과 **확실한 알림**이다.

---

## 1. 목표와 원칙

### 1.1 핵심 목표
1. 할 일과 일정을 빠르게 입력한다. 트레이나 단축키로 2초 안에 입력할 수 있어야 한다.
2. 정해진 시각에 **반드시** 알린다. 절전 복귀, 재부팅, 집중 모드 등으로 놓친 알림도 다시 보여 준다.
3. 완료된 항목과 미완료 항목이 한눈에 구분된다.
4. 트레이에 상주하는 동안 메모리를 거의 쓰지 않는다.

### 1.2 비기능 요구사항 (목표 수치)

| 항목 | 목표 |
|---|---|
| 트레이 상주(창 닫힘) 메모리 | Working Set **30MB 이하** |
| 메인 창 열림 메모리 | **100MB 이하** |
| 콜드 스타트 → 트레이 아이콘 표시 | 0.5초 이내 |
| 트레이 클릭 → 창 표시 | 0.3초 이내 |
| 알림 지연 | 예정 시각 + 1초 이내 |
| 데이터 손실 | 비정상 종료 시 최대 "자동 저장 간격"만큼(기본 1분). 편집 중 디바운스 저장으로 실제로는 수 초 이내 |
| 배포 크기 | 단독 실행형 exe 약 131MB (WPF 런타임 포함, 시작 속도를 위해 압축 안 함), 런타임 필요형 약 3MB |

### 1.3 설계 원칙
- **상주 코어와 UI 분리**: 트레이, 알림 스케줄러, 자동 저장만 항상 메모리에 둔다. 창을 닫으면 UI 객체를 해제하고 Working Set을 정리한다.
- **로컬 우선**: 모든 데이터는 로컬에 저장한다. 서버나 계정이 필요 없다. 동기화는 나중에 선택 기능으로 넣는다.
- **이벤트 기반**: 주기적 폴링 대신 "다음 알림 시각" 하나에 타이머를 건다.

## 2. 기술 스택

### 2.1 후보 비교

| 스택 | 상주 메모리 | 개발 생산성 | 한글/IME·UI 품질 | 비고 |
|---|---|---|---|---|
| C++ / Win32 | ★★★★★ (5~10MB) | ★☆☆☆☆ | 직접 구현 필요 | 달력 UI 구현 비용이 큼 |
| Rust + windows-rs/Slint | ★★★★☆ | ★★☆☆☆ | 보통 | 생태계 미성숙 |
| **C# .NET 10 + WPF** | ★★★☆☆ (창 해제 시 20~30MB) | ★★★★★ | 우수 | **추천** |
| WinUI 3 (Windows App SDK) | ★★☆☆☆ | ★★★★☆ | 우수 | 기본 메모리가 크고 배포가 번거로움 |
| Tauri (WebView2) | ★★☆☆☆ (WebView 프로세스 별도) | ★★★★☆ | 우수 | 창을 열면 100MB 이상 |
| Electron | ★☆☆☆☆ (150MB 이상) | ★★★★★ | 우수 | 요구사항에 맞지 않음 |

### 2.2 결정: **C# / .NET 10 (LTS) + WPF**
- .NET 8 지원이 2026년 11월에 끝나므로 현재 LTS인 .NET 10(2028년 11월까지 지원)을 쓴다.
- 근거: 생산성, 한글 IME 안정성, 달력/리스트 UI 구현 용이성. 메모리 문제는 아래 "상주 코어 + 필요할 때만 UI" 구조로 해결한다.
- 주요 라이브러리 (모두 가볍고 검증된 것)
  - `Microsoft.Data.Sqlite`: 할 일/일정 저장 (ORM 미사용, 직접 SQL로 시작 비용과 메모리 절감)
  - `Microsoft.Toolkit.Uwp.Notifications` (또는 `CommunityToolkit.WinUI.Notifications`): Windows 11 토스트 알림, 버튼 동작
  - `H.NotifyIcon.Wpf`: 트레이 아이콘. 또는 Win32 `Shell_NotifyIcon`을 직접 P/Invoke
  - `Ical.Net`: 반복 규칙(RRULE), ICS 가져오기/내보내기 (필요할 때 지연 로드)
- 빌드: `PublishSingleFile`, `SelfContained`, `PublishReadyToRun`(시작 속도 향상), `PublishReadyToRunComposite=false`(프레임워크는 Microsoft가 미리 컴파일한 코드를 그대로 써서 exe 17MB 절약), `InvariantGlobalization=false`(한국어 날짜 형식)
- 런타임 설정: `<ServerGarbageCollection>false</ServerGarbageCollection>`, `<ConcurrentGarbageCollection>false</ConcurrentGarbageCollection>`

> 대안: 메모리가 더 중요해지면 상주 코어(트레이+스케줄러)만 C++/Rust 프로세스로 분리하고, UI는 별도 프로세스로 띄우는 2프로세스 구조로 바꿀 수 있다. §3의 계층 분리를 지키면 이 전환이 쉬워진다.

### 3.1 프로젝트 구조


### 3.2 메모리 절약 전략
1. **창 닫기 = 해제**: `MainWindow`는 숨기지 않고 `Close()`한다. 그 뒤 `GC.Collect()`를 호출하고 `SetProcessWorkingSetSize(-1,-1)`로 Working Set을 반환한다.
2. **필요한 만큼만 로드**: 달력은 보이는 달(±1개월)의 일정만 조회한다. 리스트는 `VirtualizingStackPanel`로 가상화한다.
3. **메모 본문 지연 로드**: 메모 목록에는 제목과 미리보기 100자만 두고, 본문은 열 때 읽는다.
4. **상주 코어는 다음 알림 1건만 보유**: 전체 일정을 메모리에 올리지 않는다.
5. 무거운 기능(ICS, 검색 인덱스)은 처음 사용할 때 로드한다.
6. 애니메이션, 아크릴/미카 효과는 설정에서 끌 수 있게 한다.

## 4. 데이터 모델

### 4.1 SQLite 스키마 (data.db, 롤백 저널 모드 — §4.5)

```sql
-- 목록(프로젝트): "개인", "업무" 등
CREATE TABLE lists (
  id          INTEGER PRIMARY KEY,
  name        TEXT NOT NULL,
  color       TEXT,                -- #RRGGBB
  sort_order  INTEGER DEFAULT 0,
  is_archived INTEGER DEFAULT 0
);

-- 할 일과 일정을 하나의 테이블로 통합 (Todo에도 시간이 있을 수 있고, 일정에도 완료 체크가 가능)
CREATE TABLE items (
  id            INTEGER PRIMARY KEY,
  kind          INTEGER NOT NULL,     -- 0=Todo, 1=Event
  list_id       INTEGER REFERENCES lists(id),
  parent_id     INTEGER REFERENCES items(id),  -- 하위 할 일
  title         TEXT NOT NULL,
  notes         TEXT,
  priority      INTEGER DEFAULT 0,    -- 0 없음, 1 낮음, 2 보통, 3 높음
  is_all_day    INTEGER DEFAULT 0,
  start_at      TEXT,                 -- ISO-8601 로컬 시각; 하루종일이면 날짜만 'YYYY-MM-DD'
  end_at        TEXT,                 -- 하루종일 여러 날 일정은 end 날짜(포함)
  due_at        TEXT,                 -- Todo 마감
  rrule         TEXT,                 -- RFC 5545 RRULE (NULL이면 반복 없음)
  status        INTEGER DEFAULT 0,    -- 0 미완료, 1 완료, 2 취소
  completed_at  TEXT,
  location      TEXT,
  color         TEXT,
  sort_order    INTEGER DEFAULT 0,
  created_at    TEXT NOT NULL,
  updated_at    TEXT NOT NULL,
  deleted_at    TEXT                  -- 휴지통 (소프트 삭제)
);
CREATE INDEX ix_items_start  ON items(start_at) WHERE deleted_at IS NULL;
CREATE INDEX ix_items_due    ON items(due_at)   WHERE deleted_at IS NULL;
CREATE INDEX ix_items_status ON items(status, list_id);

-- 반복 일정에서 특정 회차의 완료/수정/건너뛰기
CREATE TABLE occurrences (
  item_id        INTEGER REFERENCES items(id),
  original_start TEXT NOT NULL,
  status         INTEGER,             -- 해당 회차만 완료/취소
  override_json  TEXT,                -- 해당 회차만 시간/제목 변경
  PRIMARY KEY (item_id, original_start)
);

-- 알림: 항목 하나에 여러 개 가능 (예: 1일 전, 10분 전)
CREATE TABLE reminders (
  id             INTEGER PRIMARY KEY,
  item_id        INTEGER REFERENCES items(id) ON DELETE CASCADE,
  offset_minutes INTEGER,             -- 시작/마감 기준 상대(-10 = 10분 전)
  absolute_at    TEXT,                -- 또는 절대 시각
  next_fire_at   TEXT,                -- 계산 결과 캐시 (스케줄러가 사용)
  snoozed_until  TEXT,
  last_fired_at  TEXT,
  is_persistent  INTEGER DEFAULT 0    -- 확인할 때까지 반복 알림
);
CREATE INDEX ix_reminders_next ON reminders(next_fire_at);

CREATE TABLE tags      (id INTEGER PRIMARY KEY, name TEXT UNIQUE, color TEXT);
CREATE TABLE item_tags (item_id INTEGER, tag_id INTEGER, PRIMARY KEY(item_id, tag_id));

-- 전문 검색 (할 일/일정 제목, 노트)
CREATE VIRTUAL TABLE items_fts USING fts5(title, notes, content='items', content_rowid='id');
```

### 4.2 하루종일 일정과 시간 단위 일정
- 하루종일: `is_all_day=1`, `start_at='2026-11-03'`, `end_at='2026-11-05'`(포함, 3일짜리). 달력 상단 "종일" 띠에 막대로 표시한다.
- 시간 단위: `is_all_day=0`, `start_at='2026-11-03T14:00'`, `end_at='2026-11-03T15:30'`. 주간/일간 뷰의 시간 그리드에 블록으로 표시한다. 입력 단위는 기본 15분이고 설정에서 5/10/15/30분 중에 고른다.
- 시간은 로컬 시각 문자열과 시간대 ID(설정)로 저장한다. 해외 이동이나 DST가 생기면 그때 UTC 컬럼을 추가한다.

### 4.3 메모 저장 (파일 기반)
메모장처럼 쓰고, 폴더별로 정리하고, 다른 편집기와도 호환되도록 **실제 폴더와 파일**로 저장한다.
기본 위치는 데이터 폴더 안의 `Notes\`다.

```
<데이터 폴더>\Notes\
  업무\
    회의록\
      2026-10-28 주간회의.md
    아이디어.md
  개인\
    장보기.txt
    .images\         # 메모에 넣은 그림 (메모와 같은 폴더, ![](.images/이름.png))
  .trash\            # 삭제된 메모 (30일 후 영구 삭제)
  .history\          # 예전 버전: .history\업무\아이디어.md\20261028-090000.md (10분에 한 번, 메모마다 30개)
```
- 점(.)으로 시작하는 폴더는 메모 트리·목록·검색에서 뺀다. 그림은 상대 경로라 폴더를 통째로 옮겨도 깨지지 않고,
  메모 하나를 다른 폴더로 옮기면 메모 안의 그림 경로를 새 위치 기준으로 고친다. 폴더를 끌어 다른 폴더로 옮기면(`MoveFolder`)
  안의 메모 중 폴더 밖 그림(`../`)을 가리키는 경로만 고친다. 자기 안·같은 이름이 있는 곳으로는 옮기지 않는다. 이름 바꾸기·이동 때 기록 폴더도 따라 옮긴다.
- 메모 목록과 미리보기는 파일 시스템을 스캔해서 만든다. 경로·수정시각·미리보기는 `notes_index` 테이블에 캐시한다.
- `FileSystemWatcher`로 외부 편집을 감지해 목록을 갱신하고, 충돌하면 사용자에게 알린다.
- 메모 위치는 설정에서 바꿀 수 있다. 데이터 폴더 안이면 상대 경로로 저장해서 복사해도 깨지지 않는다. 데이터 폴더 밖(예: OneDrive)으로 지정하면 그 폴더는 따로 옮겨야 하고, 다른 PC에 그 경로가 없으면 기본 `Notes\`를 쓴다.

### 4.5 데이터 이동 (파일 복사만으로 다른 PC에서 사용)
**요구사항**: 저장된 모든 내용(설정, 할 일/일정, 메모)은 파일 복사만으로 다른 PC에서 그대로 쓸 수 있어야 한다.

| 규칙 | 구현 |
|---|---|
| 모든 사용자 데이터는 한 폴더에 | 설정, DB, 메모, 백업, 로그를 모두 데이터 폴더 아래에 둔다 (`AppPaths`) |
| DB는 단일 파일 | SQLite WAL 대신 롤백 저널(DELETE)을 쓴다. WAL은 최근 변경이 `data.db-wal`에 남아 `data.db`만 복사하면 빠질 수 있다. 예전 WAL DB는 시작할 때 자동 전환한다 |
| 설정 파일에 PC 고유 경로를 쓰지 않음 | 메모 폴더 등은 데이터 폴더 기준 상대 경로로 저장. 절대 경로가 다른 PC에 없으면 기본값으로 대체 |
| PC 고유 상태는 데이터에서 다시 만든다 | 로그인 자동 실행(레지스트리)은 시작할 때 `settings.json` 값으로 다시 등록한다. exe 경로는 저장하지 않는다 |
| 형식은 PC와 무관 | 텍스트는 UTF-8(BOM 없음), 날짜는 ISO-8601 문자열, DB는 SQLite 표준 형식 |
| 새 버전 DB를 옛 앱이 열면 | 마이그레이션 버전을 확인해 안내 후 종료 (데이터를 건드리지 않음) |

옮기는 방법:
1. 원래 PC에서 트레이 아이콘 → **종료** (실행 중 복사도 대부분 안전하지만, 저장 도중 복사를 피하기 위해)
2. exe와 데이터 폴더(exe 옆 `Data\`, 설정 → 데이터 → **열기**)를 함께 복사
3. 새 PC 아무 폴더(쓸 수 있는 곳)에 붙여넣고 실행

테스트: `DataFolderCopyTests`가 데이터 폴더를 다른 경로로 복사한 뒤 설정·DB·메모가 그대로 열리는지 확인한다.

### 5.2 완료/미완료 시각 구분 (핵심 요구사항)
색상만으로 구분하지 않고 **아이콘, 서식, 위치**를 함께 바꾼다. 색약 사용자도 구분할 수 있어야 한다.

| 상태 | 체크박스 | 제목 | 색 | 위치 |
|---|---|---|---|---|
| 미완료 | ☐ 빈 원 (우선순위 색 테두리) | 보통 굵기 | 기본 글자색 | 위쪽 |
| 기한 지남 | ☐ 빨간 원 + ⚠ | **굵게** | 빨강 계열, 마감일 빨간 글씨 | 맨 위 |
| 완료 | ☑ 채워진 체크 | ~~취소선~~ | 회색, 투명도 50% | "완료됨 (n)" 접힘 영역으로 이동 |
| 취소 | ⊘ | ~~취소선~~ 기울임 | 회색 | 완료 영역 |

- 달력에서 완료된 일정은 블록 색을 빼고 회색 테두리에 체크(✓)를 붙인다. 미완료 과거 일정은 빗금 패턴으로 표시한다.
- 상단 진행률 표시: "오늘 5개 중 3개 완료 ▓▓▓░░ 60%"
- 설정: "완료 항목 숨기기 / 흐리게 보기 / 그대로 보기"

### 5.3 달력
- 뷰: **월 / 주 / 일 / 일정목록(Agenda)**. 단축키 `M`/`W`/`D`/`A`, 오늘로 이동은 `T`
- 월 뷰: 종일 일정은 막대로, 시간 일정은 "14:00 회의"처럼 점과 텍스트로 표시. 넘치는 항목은 "+3"
- 주/일 뷰: 상단 종일 영역과 시간 그리드. 드래그로 생성, 이동, 길이 조절. 현재 시각은 빨간 선으로 표시
- 달력에 마감이 있는 Todo도 함께 표시 (토글 가능)
- 한국 공휴일 표시 (대체공휴일 포함, 내장 데이터 + 연 단위 업데이트). 음력 표시는 선택
- 미니 달력 (사이드바), 날짜 클릭 시 그날의 일정과 할 일
- 반복: 매일/매주(요일 선택)/매월(n일, n번째 x요일)/매년/사용자 정의, 종료(횟수/날짜). 반복 일정 수정 시 "이 일정만 / 이후 모두 / 전체" 선택

### 5.4 알림 (핵심 요구사항)

#### 5.4.1 알림 종류
| 종류 | 설명 |
|---|---|
| 상대 알림 | 시작/마감 n분·시간·일 전 (여러 개 가능, 기본값 설정 가능) |
| 절대 알림 | 특정 일시 |
| 종일 일정 알림 | 당일 또는 전날 지정 시각(예: 09:00) |
| **끈질긴 알림** | 완료나 확인을 누를 때까지 n분마다 다시 알림 (중요 항목용) |
| **일일 브리핑** | 매일 지정 시각(또는 로그인 시)에 "오늘 할 일 5개, 일정 2개, 기한 지남 1개" |
| 기한 지남 알림 | 마감이 지난 미완료 항목을 하루 1회 상기 |

#### 5.4.2 알림 표시
- 기본: **앱 자체 알림 팝업** (`ReminderWindow`). 화면 오른쪽 아래, 항상 위, 포커스를 빼앗지 않음. 사용자가 처리할 때까지 남는다
  - 카드 버튼: `[✓ 완료]` `[⏰ 10분 후]` `[▾ 5분/10분/30분/1시간/3시간/내일 아침]` `[열기]` `[✕ 확인]`
  - 놓친 알림이 여러 개면 한 카드로 묶음: `[모두 확인]` `[1시간 후 다시]` `[오늘 화면 열기]`
  - 일일 브리핑 카드: 오늘 할 일 수, 기한 지남 수, 상위 6개
- **M3에서 바꾼 결정 (Windows 토스트 → 자체 팝업)**
  - 토스트는 집중 모드/알림 끄기 상태에서 숨겨져 "잊지 않게"라는 핵심 목표와 맞지 않는다
  - 설치 없는 exe에서 토스트 버튼(백그라운드 활성화)을 쓰려면 COM 등록과 AUMID 등록이 필요해 불안정하다
  - 토스트용 Windows SDK 연동 라이브러리가 들어가 exe 크기와 메모리가 늘어난다
  - Windows 알림 센터에도 기록을 남기는 기능은 필요하면 나중에 선택 기능으로 추가한다
- 트레이 아이콘: 기한 지난 할 일이나 확인하지 않은 알림이 있으면 빨간 점 아이콘. 툴팁에 남은 할 일·기한 지남·다음 알림 시각
- 트레이 메뉴: 오늘의 할 일 보기(브리핑), 알림 일시 중지(30분/1시간/3시간/내일 아침까지) / 다시 시작
- 소리: Windows 알림음(기본), 무음, 사용자 WAV 경로

#### 5.4.3 ReminderEngine 동작
```
시작 시 / 데이터 변경 시 / 절전 복귀 시 / 시간 변경 시:
  1. SELECT MIN(next_fire_at) FROM reminders WHERE next_fire_at IS NOT NULL
  2. 그 시각에 단일 타이머 설정 (System.Threading.Timer, 최대 대기 1시간마다 재계산)
타이머 만료 시:
  3. next_fire_at <= now 인 알림을 모두 조회 → 표시
  4. last_fired_at 기록, 반복/끈질긴 알림이면 next_fire_at 재계산, 아니면 NULL
  5. 1번으로
절전 복귀 / 앱 재시작 시 (놓친 알림):
  - next_fire_at < now 인 항목을 "놓친 알림 n개" 묶음 토스트로 표시
```
- `SystemEvents.PowerModeChanged`(Resume), `SystemEvents.TimeChanged`, `SessionSwitch`(잠금 해제)를 구독해서 다시 계산한다
- 반복 일정은 "다음 1회차"만 `next_fire_at`에 펼쳐 저장한다. 미래 전체를 미리 펼치지 않는다

### 5.5 메모 (메모장 기능)
- 왼쪽에 폴더 트리 (생성, 이름 변경, 이동, 삭제, 드래그앤드롭), 가운데에 메모 목록, 오른쪽에 편집기
- 편집기: 일반 텍스트(마크다운 원문) 기반. 서식 도구(굵게, 기울임, 밑줄, 취소선, 형광펜, 글자색, 코드, 링크, 제목, 목록, 체크 목록, 인용)는
  마크다운으로 넣고 "편집 / 나란히 / 보기"로 서식이 적용된 모양을 본다 (링크 열기, 체크 상자 체크 가능).
  WYSIWYG(RichTextBox) 대신 이 방식을 고른 이유: 파일이 그대로 마크다운이라 다른 편집기와 호환되고, 찾기/바꾸기·세션 복원·할 일로 만들기·
  스티커·검색이 모두 같은 원문을 쓴다. 마크다운에 없는 글자색/밑줄/형광펜은 HTML 태그(`<span style="color:#RRGGBB">`, `<u>`, `<mark>`)로 쓴다.
  미리보기는 웹·메일 링크만 연다 (file:, javascript: 차단). 탭으로 여러 메모 열기, 찾기/바꾸기(`Ctrl+F`/`Ctrl+H`), 줄 번호(선택), 자동 줄바꿈, 글꼴/크기
- **보기에서 바로 고치기 (기본)**: 메모는 "보기"로 열리고 RichTextBox에서 서식이 적용된 모양 그대로 고친다. 원문은 "편집"/"나란히"를
  직접 누를 때만 (메모 화면을 열 때마다 "보기"로 시작). 파일은 그대로 마크다운이며 **문단 하나 = 마크다운 한 줄**(`MarkdownLines`:
  빈 줄·목록 들여쓰기·코드 블록까지 줄 구조를 지켜 `Write(Parse(md)) == md`, 모르는 문법·태그는 글자로 남김)이다.
  목록 기호·번호·체크 상자는 문단 맨 앞의 작은 요소, 제목·인용·코드는 문단 표시, 글자 서식은 Run의 로컬 값(굵기·기울임·밑줄/취소선·배경·색·코드 글꼴)으로
  읽고 쓴다. 고치면 250ms 뒤 마크다운으로 바꿔 탭 내용에 반영(자동 저장·기록·검색은 그대로). 붙여 넣기는 글자만(그림은 .images로),
  마크다운으로 저장할 수 없는 RichTextBox 기본 서식(정렬·글자 크기·줄 간격)은 막는다.
- **옵시디언 모드** ("옵시디언" 단추, 설정에서 시작 방식으로 고를 수 있음): Obsidian의 라이브 미리보기처럼 원문을 그대로 고치되
  서식을 입혀 보인다. 편집기는 AvalonEdit(`LivePreviewEditor`)이고 문서 내용이 곧 마크다운 원문이라 저장·실행 취소·찾기·서식 도구는
  원문 편집과 같다(`IMarkdownTarget`으로 원문 TextBox와 같은 명령을 씀). 줄마다 `LivePreview.ParseLine`(Core, 단위 테스트)이
  서식 범위(제목 크기, 굵게·기울임·취소선·`==형광==`·코드·링크·`<span style="color">`)와 서식 기호 위치를 알려 준다.
  커서(선택)가 걸친 줄은 기호를 흐리게 보이고, 다른 줄은 기호를 숨기거나(폭 0) 글머리표·체크 상자(누르면 `[ ]`↔`[x]`)·가로줄·그림으로 바꿔 그린다.
  코드 블록(울타리 상태는 문서 전체로 계산)과 표는 고정폭 글꼴로 원문 그대로. Enter는 목록·번호·체크·인용을 잇고(빈 항목이면 끝냄),
  Tab/Shift+Tab은 목록 줄 들여쓰기(공백 2칸). 링크는 Ctrl+클릭(웹·메일만), `[[메모]]`는 같은 이름의 메모를 연다.
- **자동 저장**: 수정 후 3초 디바운스 + N분 주기 + 창 포커스 잃을 때. 저장 상태 표시: "● 수정됨" / "✓ 저장됨 14:32"
- **세션 복원** (Notepad++ 방식): 앱을 종료했다가 다시 열면 열려 있던 탭과 저장 안 된 내용, 커서 위치까지 복원
- 메모 고정(핀), 메모에서 체크리스트 `- [ ]` 줄을 선택해 할 일로 변환
- 메모 검색: 제목과 본문 전체 검색 (폴더 범위 지정). 마크다운은 "보기"에 보이는 글자(`MarkdownLines.ToPlainText`: 서식 기호·태그·목록 기호·
  링크 주소·그림 경로 제외)에서 찾고 그 글자로 결과 일부를 보인다. 전체 검색의 할 일·일정 메모도 같다
- 그림: Ctrl+V(클립보드에 글자 없이 그림만 있을 때 PNG로 저장, 그림 파일 복사도 받음), 🖼 단추, 파일 끌어다 놓기.
  미리보기는 메모 폴더 안의 파일만 읽고(인터넷 그림은 설명 글자만), 큰 사진은 1440px로 줄여 읽어 메모리를 아낀다.
  "보기"에서 그림을 누르면 그림이 선택되고 테두리·네 모서리 손잡이(ImageResizeAdorner)가 보인다. 끌면 너비만 바꾸고 높이는 비율대로
  (최소 24px, 최대 720px). 너비는 Obsidian처럼 `![설명|너비](경로)`로 쓰고, 너비가 없으면 원래 크기(큰 그림은 줄여서)로 보인다.
- 표: GFM 표(`MarkdownTable`). 머리글 줄과 구분 줄(`| --- | ---: |`) 모두 `|`가 있어야 표로 읽는다(가로줄 `---`과 헷갈리지 않게),
  이어지는 `|`가 있는 줄까지가 표다. 미리보기·"보기"에서는 테두리 칸(Grid)으로 그리고, "보기" 편집기에서는 표 전체가 한 블록(BlockUIContainer)이다.
  칸을 누르면 그 칸 자리에 글 상자를 띄워 칸의 마크다운을 그대로 고친다(`\|`는 `|`, `<br>`은 줄바꿈으로 보임. 서식 기호는 그대로 두어 고쳐도 서식이
  없어지지 않는다). Tab/Shift+Tab·Enter로 칸을 옮기는 동안은 화면만 바꾸고, 표 밖으로 나갈 때(다른 곳을 누름, 마지막 칸, Esc) 고친 표로 블록을
  한 번 바꿔 실행 취소 한 번에 되돌린다. 고치는 중에도 저장은 고친 내용으로 한다(`ToLines`가 글 상자 글자를 읽음). Esc는 표 전체 선택(Delete·Ctrl+C),
  표를 고른 채 Enter·F2는 첫 칸부터 고친다. 붙여 넣기: 클립보드에 엑셀 형식(XML Spreadsheet·CSV)이나 HTML 표가 함께 있으면
  탭으로 나뉜 글자를 표로 바꾼다(첫 줄 = 머리글, 숫자만 있는 열은 오른쪽 정렬, 칸 안의 서식 기호·`|`는 이스케이프, 줄바꿈은 `<br>`).
  "편집"에서는 앞뒤 글과 빈 줄로 떼어 넣는다.
- 버전 기록: 저장 직전 내용이 바뀌었고 마지막 버전에서 10분이 지났으면 파일을 `.history`로 복사한다. 기록 창에서 미리보고 되돌리며,
  되돌리기 전 내용도 버전으로 남긴다.
- 데스크톱 스티커 메모 (선택): 메모 하나를 항상 위 작은 창으로 띄우기 (Windows 스티커 메모 참고)

### 5.5.1 워크플로우 (Excalidraw 방식 그림판)
- 탐색 메뉴 "✏ 워크플로우": 왼쪽은 그림 목록(＋ 새로, 오른쪽 클릭 → 이름 바꾸기·복사본·탐색기에서 보기·삭제, 파일 가져오기),
  오른쪽은 손그림 느낌의 그림판. 그림은 `Data\Drawings\이름.excalidraw`(Excalidraw JSON, `type: "excalidraw"`, `version: 2`)로
  1.5초 뒤 자동 저장하며, 파일 그대로 excalidraw.com이나 Obsidian Excalidraw에서 열린다. 지우면 `Drawings\.trash`로 옮긴다. 백업 zip에도 들어간다.
- 호환: 요소는 JSON 객체를 그대로 들고 아는 속성만 고친다(`ExcalidrawElement`). 모르는 속성·`appState`의 다른 설정·`files`(그림)는
  읽은 그대로 다시 쓴다. 지우기는 Excalidraw처럼 `isDeleted: true`, 고칠 때마다 `version`/`versionNonce`/`updated`를 올린다.
- 도구: 선택 V, 손 H(또는 Space+끌기·휠 가운데 단추), 사각형 R, 마름모 D, 원 O, 화살표 A, 선 L, 펜 P, 글자 T, 지우개 E (숫자 1~8, 0도 같음).
  Ctrl+휠 확대/축소, 휠 위아래·Shift+휠 좌우 이동, Shift+1 전체 보기, Ctrl+0 100%.
- 편집: 누르기·Shift+누르기·끌어서 여러 개 선택, 끌어 옮기기, 손잡이로 크기(Shift는 비율 유지), 화살표 키로 1px(Shift 10px),
  Delete, Ctrl+D 복제, Ctrl+C/X/V(Excalidraw 클립보드 형식이라 excalidraw.com과 서로 붙여 넣기 가능, 일반 글자는 글자 요소로),
  Ctrl+Z/Ctrl+Y 되돌리기(200번). 도형을 두 번 누르거나 Enter → 도형 안 글자(boundElements/containerId, 가운데 맞춤, 넘치면 도형을 키움).
  빈 곳을 두 번 누르면 글자. Esc·Ctrl+Enter로 글자 고치기 끝.
- 연결: 화살표를 그리거나 끝을 끌면 마우스 근처 도형의 **연결점**(위·오른쪽·아래·왼쪽 가운데, 마름모는 꼭짓점)이 보이고,
  14px 안이면 그 점에 달라붙는다. 연결점에 놓은 끝은 `startBinding`/`endBinding`의 `fixedPoint`(도형 상자 안 비율, Excalidraw와 같은 이름)로
  저장되어 도형을 옮기거나 크기를 바꿔도 그 점(+4px)을 따라간다. 연결점이 아닌 도형 위에 놓으면 예전처럼 반대쪽을 향해 테두리에 붙는다(+6px).
- 곡선 화살표: 새 화살표·선은 Excalidraw처럼 둥근 선(`roundness: {type: 2}`)이라 점을 넣으면 부드럽게 휜다. 선을 고르면 점마다 원 손잡이와
  구간 가운데의 흐린 손잡이가 보이고, 가운데 손잡이를 끌면 점이 생겨 굽는다. 가운데 점을 두 번 누르면 지운다. 속성 창에서 직선/곡선.
- 워크플로우 도우미: 도형 하나를 고르고 Ctrl+→↓←↑ → 같은 모양·크기·색의 다음 단계를 80px 옆에 만들고 화살표로 잇는다(자리가 차 있으면 비켜 놓음).
- **Excalidraw와 같은 모양**: 손그림은 rough.js 4.6.4(`Core/Drawings/Rough`), 펜은 perfect-freehand 1.2.0, 요소별 규칙(거칠기 보정,
  둥근 모서리 반지름, 마름모 꼭짓점, 곡선, 화살촉, 닫힌 선 채우기)은 Excalidraw 0.18의 Shape.ts를 C#으로 옮겼다(`ExcalidrawShapes`).
  같은 seed면 원본과 같은 난수 순서로 같은 좌표가 나온다. 검증: `tools/excalidraw-ref`가 진짜 rough.js·Excalidraw(헤드리스 Chromium)로
  만든 결과(rough.js 243가지, 샘플 14개의 SVG)와 테스트에서 숫자 하나하나 비교한다(`RoughGoldenTests`, `ExcalidrawShapeGoldenTests`).
  화면은 그 결과를 canvas와 같은 방식으로 칠한다(채우기 → 빗금(굵기 = 선 굵기/2) → 테두리, 둥근 선 끝, Excalidraw 점선 간격 `[8, 8+굵기]`·`[1.5, 6+굵기]`).
  UI 테스트는 같은 샘플을 앱에서 열어 스크린샷(`wf-*.png`)을 남긴다.
- 글꼴·글자: Excalidraw 글꼴을 앱에 넣었다(Excalifont, Virgil, Nunito, Lilita One, Comic Shanns, 한글은 Xiaolai의 한글 부분, `Assets/Fonts`).
  글자는 Excalidraw처럼 줄마다 글꼴 지표(ascender/descender/줄 높이)로 기준선을 잡는다. `text`에는 줄바꿈한 결과, `originalText`에는 입력 그대로,
  상자 안 글자는 여백 5(원·마름모는 안쪽 사각형), 넘치면 상자 높이를 키우고, 화살표 글자는 가운데 지점에 두고 그 아래 선을 비운다.
- 색: Excalidraw 색 고르기와 같다(`ColorPicker.cs`의 `ExcalidrawPalette`, open-color 0·2·4·6·8번 명도 + radix bronze). 줄마다 자주 쓰는 5색과
  지금 색 칸, 지금 색을 누르면 15가지 색 → 5단계 명도(색 이름을 누르면 선은 4번째, 채우기는 2번째 명도), 그림에서 쓴 다른 색(최대 5), `#` 색 코드 입력.
  불투명도(`opacity` 0~100), 바탕색(`appState.viewBackgroundColor`, Excalidraw 바탕 5가지 + 모든 색).
- 모양: 선 색·채우기 색(Excalidraw 기본 팔레트), 칠하기/빗금/엇갈린 빗금/지그재그, 굵기, 실선/점선/작은 점, 손그림 정도(반듯하게 0/손그림 1/더 거칠게 2),
  모서리(각지게/둥글게), 화살표 모양(직선/곡선)과 시작·끝 머리(화살·삼각형·막대·점·원·마름모), 글꼴(손글씨/보통/만화/코드), 글자 크기.
  고른 값은 다음에 그릴 도형에도 쓴다. 어두운 테마에서는 Excalidraw처럼 모든 색에 invert(93%) + hue-rotate(180°)를 적용해 보이고 파일 색은 그대로다.
- 내보내기: PNG 저장, 그림 복사(선택한 것만 또는 전체, 2배 크기, 파일의 배경색).
- 아직 없음: 회전 손잡이, 그룹 묶기/풀기(파일의 groupIds는 유지), 꺾인(elbow) 화살표, 그림 파일 넣기, Obsidian의 `.excalidraw.md` 형식.

### 5.6 자동 저장 (분 단위 옵션)
- 설정: 저장 간격 **1~60분** (기본 1분), "편집 후 즉시 저장(디바운스 n초)" 켜기/끄기
- 구현: 각 편집 대상이 `IDirty`를 구현한다. `AutoSaveService`가 주기 타이머로 더티 객체만 저장한다
- 저장 안전성
  - SQLite: 롤백 저널(DELETE) + `synchronous=FULL` + 트랜잭션. 커밋이 끝나면 모든 데이터가 `data.db` 한 파일에 있다
  - 메모 파일: `임시파일 쓰기 → File.Replace()` 원자적 교체 (저장 중 전원이 꺼져도 파일이 깨지지 않음)
- 자동 백업: 하루 1회 `data.db`와 Notes를 zip으로 백업 (`<데이터 폴더>\Backups`, 최근 14개 보관). 설정에서 백업 위치를 바꿀 수 있다

### 5.7 빠른 입력 (Quick Add)
- 전역 단축키 `Ctrl+Alt+Space` 또는 트레이 메뉴 → 화면 중앙에 Spotlight 같은 한 줄 입력창
- **자연어 파싱** (Todoist, TickTick 방식, 한국어 우선)
  - `내일 오후 3시 치과 #개인 !높음` → 일정, 내일 15:00, 목록 "개인", 우선순위 높음
  - `금요일까지 보고서 제출` → Todo, 마감 이번 주 금요일
  - `매주 월요일 9시 주간회의 10분전 알림` → 반복 일정, 알림 -10분
  - `11/3~11/5 제주 여행` → 3일짜리 종일 일정
  - 인식된 부분은 입력 중에 색으로 강조하고, 아래에 해석 결과를 미리 보여 준다
- `Enter` 저장, `Esc` 취소, `Tab`으로 상세 입력 전환

| 메모 | `Ctrl+V` | 클립보드 그림 붙여 넣기 |

다른 프로그램과 겹칠 수 있으므로 전역 단축키는 하나씩(`hotkeys.*Enabled`), 메모 서식 단축키(`notes.formatShortcuts`)와
그림 붙여 넣기(`notes.pasteImages`)는 설정에서 끌 수 있다. 끈 전역 단축키는 등록을 풀어 다른 프로그램이 쓸 수 있다.

## 8. 배포 / 설치
- 단일 exe 두 종류: 단독 실행형(Self-contained, 약 131MB, 설치 필요 없음)과 런타임 필요형(약 3MB, .NET 10 Desktop Runtime 필요) + 선택적으로 **MSIX** 패키지. MSIX로 배포하면 토스트 COM 등록과 시작 프로그램 등록이 간단하다
- 비 MSIX(포터블)일 때: 첫 실행 시 시작 메뉴 바로가기와 AppUserModelID를 등록한다 (토스트 표시에 필요)
- 데이터 위치: 기본은 exe 옆 `Data\` (exe와 함께 옮기면 끝). exe 폴더에 쓸 수 없으면 `%APPDATA%\DayDeck`. 예전 기본 위치(%APPDATA%)의 데이터는 처음 한 번 복사해 온다 (원본 유지)
- 자동 업데이트: **설치는 항상 사용자 확인 후.**
  - 릴리스: main에 들어온 커밋의 `<Version>`에 릴리스가 없으면 CI(`release` 작업)가 `v버전` 릴리스를 만든다.
    파일은 `DayDeck-버전-win-x64.zip`(단독 실행형), `…-framework-dependent.zip`, `SHA256SUMS.txt`, 설명은 CHANGELOG.md의 그 버전 구역.
  - 확인: 시작 2분 뒤, 그 뒤 한 시간마다 기한을 보고 20시간에 한 번 `api.github.com/repos/aydenchoi/DayDeck/releases/latest`를 읽는다
    (설정 `updates.checkAutomatically`, 마지막 확인·건너뛴 버전은 app_state). 초안·시험판·`v1.0-beta` 같은 태그는 무시.
  - 묻기: 새 버전이면 창에 바뀐 점을 보이고 "지금 업데이트 / 나중에 / 이 버전 건너뛰기".
  - 설치: 실행 중인 판(런타임 포함 여부)에 맞는 zip을 이 저장소의 릴리스 주소에서만 받고, SHA-256(GitHub digest 또는 SHA256SUMS.txt)이
    맞을 때만 푼다 → 저장(FlushAll)·백업 → 실행 중인 exe를 `.old`로 이름 바꾸고 새 파일 복사(실패하면 되돌림) → 끝낸 뒤 단일 인스턴스를 놓고
    `--updated`로 새 버전 시작 → 새 버전이 `.old`를 지우고 트레이 알림. `Data\`는 건드리지 않는다.
  - exe 폴더에 쓸 수 없거나 개발 빌드면 릴리스 페이지를 연다.

## 9. 테스트 전략
- **단위 테스트 (Core)**: QuickAddParser(한국어 날짜 표현 100개 이상 케이스), RecurrenceExpander, ReminderEngine 다음 시각 계산(DST, 월말, 윤년), AutoSave 원자적 저장
- **시간 추상화**: `IClock` 인터페이스로 현재 시각을 주입해서 알림 로직을 결정적으로 테스트
- **통합 테스트**: 임시 디렉터리의 SQLite와 Notes 폴더로 저장소 테스트
- **성능 측정**: 트레이 상주 1시간 후 Working Set, 일정 10,000건에서 월 뷰 렌더링 시간 (CI에서 측정 기록)
- **수동 테스트 체크리스트**: 절전 복귀 후 놓친 알림, 집중 모드 중 알림, 재부팅 후 자동 실행

글꼴: 설정 → 화면에서 화면 글꼴과 글자 크기(기본 16pt. 화면은 14pt 기준으로 만들었으므로 모든 창을 FontSize/14 비율로 확대하고, 창 크기도 그만큼 키우되 작업 영역 안으로 제한. 예전 설정의 기본값 14는 한 번 16으로 올림), 메모 편집기 글꼴·크기를 고른다. 고른 글꼴에 한글이 없으면 맑은 고딕으로 대신한다.

화면 배치: 구역 경계선(PaneSplitter)을 끌어 탐색 메뉴·할 일 상세·메모 폴더/목록/미리보기 너비를 바꾸고, 놓을 때 app_state(`layout.panes`)에 저장한다.
메인 창 위치·크기·최대화는 닫을 때 `layout.main-window`에 저장하고, 다른 PC에서 화면 밖이면 화면 안으로 들인다.

메모 그림·버전 기록·단축키 켜기/끄기: §4.3, §5.5, §6.4.

주간업무보고(`WeeklyReportPage`, Core `ReportWeek`/`WeeklyReport`): 한 주는 월~금, 주차는 목요일 기준(목요일의 해·달, 그 달의 몇째 목요일).
메모 폴더의 `주간업무보고/연도/연도-월 n주차.txt`에 저장한다(메모 검색·기록·백업·휴지통을 그대로 쓴다). 화면은 제목·머리글을 보여 주기만 하고
금주실적·차주계획 두 칸만 입력받으며, 저장할 때마다 제목과 날짜를 주차에서 다시 쓴다(파일을 손으로 고쳐 날짜가 틀려도 다음 저장 때 바로잡힘).
아무것도 쓰지 않은 주는 파일을 만들지 않고, 새 주는 지난주 차주계획을 금주실적에 미리 넣는다. 날짜 범위는 공휴일과 관계없이 월~금.

남은 선택 기능: Mica 배경, 메모 줄 번호·마크다운 강조, MSIX, 자동 업데이트.
